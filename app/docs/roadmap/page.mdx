# Roadmap

react-native-kernel is being built in phases. Shipped so far:

- ✅ `kernel/system` — device info, network state, battery
- ✅ `kernel/network` — API client, offline queue, file upload
- ✅ `kernel/storage` — secure storage, offline sync
- ✅ [`kernel/auth`](/docs/auth) — biometric unlock, session/inactivity toolkit
- ✅ [`kernel/permissions`](/docs/permissions) — unified request/check API + fallback UI
- ✅ [`kernel/media`](/docs/media) — QR, barcode, and document scanning
- ✅ [`kernel/picker`](/docs/picker) — pick any file type, with URI or streamed base64 content
- ✅ [`kernel/updates`](/docs/updates) — App Store / Play Store version check

<Callout type="warning">
  Everything below this line is **planned, not implemented**. If you `import`
  from this subpath today, it won't resolve.
</Callout>

### `kernel/ui` (next)

- `<OTPInput length={4 | 6} />` — auto-focus, paste support, Android SMS
  autofill
- `<Marquee>` — looping scrolling text
- `<NetworkImage>` — disk + memory caching, blurhash placeholder, offline
  fallback

This is also where SSID/BSSID access on Android (`ACCESS_FINE_LOCATION`)
gets a proper *request* flow via `kernel/permissions` — today
`kernel/system` only *checks* that permission, it never requests it.
