# Introduction

**react-native-kernel** is an all-in-one, modular utility toolkit for React
Native apps. It covers the plumbing almost every app needs — device and
network state, an API client, secure storage, biometric auth, permissions,
QR / document scanning, file picking, update checks and a JSON-driven
navigation drawer — in one package.

The goal is to replace 8–10 separate small npm installs with one well-typed,
tree-shakeable package.

## What makes it different

| | react-native-kernel |
| --- | --- |
| **One install** | One package, one version number and one native-linking step cover nine modules. Upgrading React Native means checking one compatibility matrix, not nine. |
| **No third-party JavaScript** | The package's `dependencies` is empty; `react` and `react-native` are its only peers. Nothing else ends up in your bundle or your audit report. |
| **Built on the platform** | Features call the OS directly — Keychain and Keystore, `fetch`, `NWPathMonitor`, `ConnectivityManager`, VisionKit, the system file picker — instead of wrapping another library. |
| **Real system UI** | The scanner, biometric prompt and file picker are the operating system's own screens, so they already match your users' language, accessibility settings and look. |
| **Tree-shakeable subpaths** | `react-native-kernel/storage` never pulls in `react-native-kernel/network`. You only ship what you import. |
| **New Architecture only** | Every native module is a TurboModule written against Codegen from the start. There is no legacy-bridge fallback to maintain. |
| **Typed end to end** | Real `.d.ts` declarations ship in the package, so editors and `tsc` see every hook, option and result type — with honest notes where a platform limits what is possible (permission-gated or OS-locked fields). |
| **Dependencies are disclosed** | The only external native code is on Android — `androidx.biometric` and Google Play Services scanners — and it is named in the docs, not hidden. |

### Check it yourself

```sh
npm view react-native-kernel dependencies        # prints nothing: no runtime dependencies
npm view react-native-kernel peerDependencies    # react and react-native only
npm pack react-native-kernel --dry-run           # lists every file you would install
```

## Design principles

- **Zero unnecessary dependencies.** The package has no runtime
  dependencies of its own — every feature is built directly on platform
  APIs (Keychain, Android Keystore, `fetch`, `NWPathMonitor`,
  `ConnectivityManager`, …).
- **Full TypeScript, no `any`.** Every hook, function, and native field is
  typed, including honest platform-limitation notes in doc comments (e.g.
  fields that are permission-gated or OS-restricted).
- **Tree-shakeable subpaths.** `import ... from 'react-native-kernel/system'`
  only bundles that module — importing `kernel/storage` never pulls in
  `kernel/network`.
- **New Architecture only.** Every native module is a TurboModule written
  against Codegen from day one. There is no legacy bridge fallback.

## Import style

Every module is imported from its own subpath so unused modules aren't
bundled:

```ts
import { useNetwork, useDeviceInfo } from 'react-native-kernel/system';
import { createApiClient } from 'react-native-kernel/network';
import { SecureStorage, useOfflineSync } from 'react-native-kernel/storage';
```

There is no root-level `react-native-kernel` import — importing the package
root exports nothing on purpose, to keep subpath imports honest about what
they pull in.
